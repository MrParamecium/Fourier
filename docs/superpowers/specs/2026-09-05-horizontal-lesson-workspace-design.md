# Graphical Convolution 横向教学工作区设计规范

## 文档状态

- 日期：2026-09-05
- 范围：2.4-2 Graphical Convolution 前两页及其课程工作区布局
- 当前阶段：设计已确认，等待 spec 审核
- 沟通语言：中文
- 产品语言：页面标题、按钮、Tutor 文案保持英文

## 1. 目标与问题

当前页面的外框虽然已经有左侧导航、中间讲解和右侧 Tutor，但第 2 页 Demo 内部仍是上下堆叠：图形、步骤和输出被连续压缩，导致用户感觉页面主要在“纵向滚动”，而不是在一个横向工作区里观察图形并操作。

本轮目标：

1. 把讲解页设计成横向主工作区，课程内容始终是视觉焦点。
2. Tutor 作为上下文辅助区放在右侧，默认可收起，不抢占图形阅读空间。
3. 第 1 页和第 2 页遵循同一阅读方向：左侧引导，右侧视觉或交互结果。
4. 保留 `1.1-2 Signal Power` 已确认的浅色彩框、清晰层级、公式提醒和 bullet point 风格。
5. 窄屏才切换到上下布局；桌面宽度下不把主要 Demo 拆成连续纵向卡片。

## 2. 已确认的整体布局

### 2.1 三个区域

```text
Tutor 收起
┌──────┬───────────────────────────────────────┐
│ 68px │          居中的课程与 Demo            │ ●
└──────┴───────────────────────────────────────┘

Tutor 展开
┌──────┬──────────────────────────┬────────────┐
│ 导航 │     Lesson / Demo 66%    │ Tutor 34%  │
└──────┴──────────────────────────┴────────────┘
```

- 左侧导航：展开状态约 `68px`，使用图标和短 Tooltip；不得继续占用当前约 `212px` 的宽度。
- 主讲解区：Tutor 展开时占剩余工作区约 `66%`。
- Tutor：Tutor 展开时占约 `34%`，保持独立滚动和输入区。
- Tutor 收起：右侧只显示一个有明确 Tutor 标识的悬浮球/窄条，主讲解区自动扩展并保持内容居中。
- Tutor 展开与收起必须是同一页面状态切换，不得创建第二套 lesson 或 Demo 实例。

### 2.2 Tutor 行为

- 默认状态：收起。
- 展开触发：点击 Tutor 球或键盘可访问的同等按钮。
- 收起触发：Tutor 右上角的明确 `Collapse tutor` 控件，或再次点击 Tutor 球。
- 面板展开/收起使用宽度和透明度的短过渡；不得移动或缩放主 Demo 的数学内容本身。
- Tutor 面板保留当前 lesson 上下文、输入框、Guided/Direct 等既有状态。
- 收起后 Tutor 球必须具备 `Tutor` 文案或可见图标，不能只显示难以理解的装饰圆点。

## 3. 课程页内部布局

### 3.1 第 1 页：Why

```text
┌──────────────────────────────┬──────────────────────────────┐
│ 标题、目的、三个理由 42%     │ 总结图 / 章节视觉 58%          │
│                              │                              │
│ · Handle complex signals     │                              │
│ · See the result clearly     │                              │
│ · Work without exact formulas│                              │
└──────────────────────────────┴──────────────────────────────┘
```

- 左侧负责短文案和顺序引导，不再把三个理由堆满整页宽度。
- bullet point 必须使用可见的 `·` 或同等圆点，不使用依赖字体渲染的隐形符号。
- 右侧显示用户已确认的单张章节总结图；图片缩放以完整可见为准，不裁切关键元素。
- 原因文案维持精简版，优先显示标题和一句解释；避免重复 what/why/how 的长段落。

### 3.2 第 2 页：Demo

```text
┌────────────────────────────┬────────────────────────────────────┐
│ 公式 + 任务引导 32%        │ GeoGebra / convolution Demo 68%   │
│                            │                                    │
│ Formula reminder           │ Signals → Product → Output        │
│ Step 1 / Step 2 / Step 3   │ 共享 t 控件、坐标轴、反馈          │
│ 当前输出                   │                                    │
└────────────────────────────┴────────────────────────────────────┘
```

- 左侧保持稳定宽度，内容顺序为：目标句、公式提醒、当前步骤、下一步动作、当前输出。
- 右侧 Demo 是本页唯一视觉焦点，给坐标图和交互控件最多空间。
- `Signals → Product → Output` 三层图在 Demo 内部保持教材要求的上下因果顺序；“左右布局”指的是引导区与 Demo 的关系，不把三层数学图横向拆开。
- 三层图之间保留明显留白，坐标轴比例保持 `1:1`；不得因为填满宽度而拉伸横轴。
- 右侧 Demo 允许内部滚动，但默认桌面尺寸应尽量在单屏显示标题、三层图和共享控件。

## 4. 响应式规则

| 视口 | 布局规则 |
| --- | --- |
| `>= 1180px` | 68px 导航 + 66/34 主区/Tutor；Why 和 Demo 均使用横向内部布局 |
| `760px–1179px` | 导航仍窄化；Tutor 可保持右侧但最低宽度不低于可读阈值，Demo 内部比例可调整到 38/62 |
| `< 760px` | Tutor 改为底部抽屉或浮层；第 1、2 页内部切换上下布局；不产生横向溢出 |
| 高度不足 | 保留比例和坐标轴，允许 Demo 内部滚动；不通过压扁图形换取“看起来一屏显示” |

## 5. 视觉与交互约束

- 颜色延续 `Signal Power` 风格：浅蓝用于目标/例子，浅绿用于概念，浅黄用于步骤，浅粉用于输出，浅紫用于公式。
- 不使用深绿色、深色背景、花哨渐变或装饰性背景纹理作为主要视觉层。
- 一屏只保留一个主焦点：第 1 页是总结图，第 2 页是 GeoGebra Demo；Tutor 为辅助焦点。
- 颜色只表达语义，不用三种高饱和颜色分别装饰三个区域。
- 交互按钮必须有明确文字或 Tooltip；例如 `Open Tutor`、`Collapse tutor`、`Choose interval`、`Move t`。
- 所有展开/收起、滑块和按钮需要键盘焦点、可见 focus ring 和 ARIA label。

## 6. 数据流与实现边界

现有 lesson 数据和 Demo 数学逻辑保持不变：

```text
lesson cache
  -> lesson renderer
  -> horizontal lesson workspace
  -> Why / Demo page layout
  -> existing GeoGebra or convolution demo instance
```

允许修改：

- lesson workspace 的 grid/flex 结构、窄导航和 Tutor 展开状态。
- 前两页的内部布局容器和卡片排列。
- Tutor 球、展开/收起控件及其响应式行为。
- 与布局直接相关的尺寸、间距、可访问性标签和断点测试。

不修改：

- 教材函数、卷积计算、共享 `t` 的数学定义和既有练习判定。
- 其他章节的内容或 Demo，除非它们共用的 workspace 外壳需要保持兼容。
- 用户已存在的无关工作区改动和 lesson cache 内容。

## 7. 失败与恢复

- Tutor 状态异常时，主讲解区仍可独立阅读和操作；不得因为 Tutor 加载失败隐藏课程内容。
- GeoGebra 加载失败时，沿用当前静态图和 Retry；布局仍保持左引导、右 Demo 的结构。
- 窄屏空间不足时，切换到安全的上下布局，不裁切公式、坐标轴、反馈或按钮。
- Resize 时只更新同一 workspace 和同一 Demo 实例，不重复挂载监听器或创建第二个 applet。

## 8. 验收标准

| ID | 验收标准 |
| --- | --- |
| AC-01 | 桌面宽度下左导航约 68px，Tutor 展开时主讲解/Tutor 约 66/34。 |
| AC-02 | Tutor 默认收起；收起后主讲解区扩展且内容居中，Tutor 球带明确 Tutor 识别。 |
| AC-03 | 第 1 页使用约 42/58 的“理由 / 总结图”左右布局，三个 bullet 的 `·` 清晰可见。 |
| AC-04 | 第 2 页使用约 32/68 的“公式步骤 / Demo”左右布局。 |
| AC-05 | 第 2 页 Demo 内部 Signals、Product、Output 仍上下排列，并保留三层留白和等比例坐标。 |
| AC-06 | Tutor 展开/收起不会重置页面、滑块、公式或 Demo 状态。 |
| AC-07 | `>=1180px`、`760–1179px` 和 `<760px` 三档布局无横向溢出、无内容裁切。 |
| AC-08 | 键盘可访问 Tutor 展开/收起、翻页、步骤控件和 Demo 交互；焦点状态清晰。 |
| AC-09 | 既有卷积、GeoGebra、练习和移动端回归测试保持通过。 |

## 9. 验证计划

1. 静态契约：检查 workspace 的列比例、Tutor 默认状态、内部布局类名和无重复 Demo 实例。
2. 浏览器检查：在 `1440×900`、`1280×720`、`1024×768`、`390×844` 下观察前两页、Tutor 展开/收起和翻页状态。
3. 几何检查：验证第 1 页 42/58、第 2 页 32/68 的近似比例，确认 Demo 坐标 x/y 单位仍相等。
4. 可访问性检查：键盘 Tab 顺序、按钮名称、focus ring、折叠状态和窄屏操作。
5. 回归检查：运行现有 convolution layout、GeoGebra、Practice、mobile 和相关 CSS 检查。

## 10. 交付边界

本轮 spec 只定义横向工作区和前两页布局，不开始代码实现。实现阶段应先依据本 spec 生成 implementation plan，再逐步修改并让用户验收视觉结果。
